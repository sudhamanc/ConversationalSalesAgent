# Serviceability Agent - Integration Guide (superseded)

> **Superseded.** The previous guide described importing the agent into the
> SuperAgent process (importlib isolation), editing SuperAgent routing, and a
> standalone `main.py` server. None of that applies after the ADK 2.x / A2A rewrite.

Current integration:

1. **Tools** are provided by the serviceability service
   ([services/serviceability/README.md](../services/serviceability/README.md)): REST under
   `/api/v1` for other systems, MCP at `/mcp/` for agents.
2. **The agent** (`serviceability_agent`) is its own A2A service
   (`serviceability_agent/server.py`) that uses `McpToolset` at `SERVICEABILITY_MCP_URL`.
3. **The gateway** calls the agent over A2A, forwards journey context in request
   metadata, and merges `_context_update.serviceability_context` from tool
   responses into its session (see [README: Agent Service Guide](../README.md#agent-service-guide) §4).
4. **Coverage data** lives in PostgreSQL `coverage_zones` (`db/migrations/004_coverage.sql`,
   seed `db/seed/003_coverage.sql`, generated by `scripts/export_coverage_seed.py`).
   `USE_MOCK_DATA=false` switches the service to the upstream GIS API
   (`GIS_API_URL`, `GIS_API_KEY`).

See [AGENTS.md](AGENTS.md) for tool contracts and the `serviceability_context` shape.
