# Catalog Service

Single source of truth for the 16 sellable SKUs and product documentation.
The same logic (`catalog_service/core.py`) is served two ways:

- **REST API** under `/api/v1`, for other systems.
- **MCP server** at `/mcp/` (streamable HTTP, stateless, JSON responses), for agents.
  `product_agent` consumes it through ADK `McpToolset`.

Pricing is **never** disclosed by this service. `unit_price` and `family` are stored in
`products` for offer management, but no endpoint or tool returns them.

## Layout

```text
services/catalog/
├── catalog_service/
│   ├── app.py          # FastAPI app: REST routers, /healthz, MCP mount, lifespan
│   ├── core.py         # business logic shared by REST and MCP (returns pydantic models)
│   ├── models.py       # pydantic models
│   ├── repository.py   # psycopg queries on `products`
│   ├── rag.py          # ChromaDB knowledge index (chunking, build, search)
│   └── mcp_server.py   # MCPServer with the 8 tools
├── data/product_docs/  # knowledge source documents (markdown)
├── scripts/ingest_knowledge.py
├── tests/
├── Dockerfile  pyproject.toml
```

Schema: `db/migrations/002_catalog.sql`. Seed: `db/seed/002_catalog.sql`, generated by
`scripts/export_catalog_seed.py` (repo root).

## REST API

| Method | Path | Notes |
|---|---|---|
| GET | `/healthz` | 200 `{status: ok, knowledge: {...}}`, 503 when the DB is unreachable |
| GET | `/api/v1/products?category=` | available products; category aliases accepted (`fiber`, `sdwan`, `voice`, `mobile`, ...) |
| GET | `/api/v1/products/{product_id}` | case-insensitive id; 404 when unknown |
| GET | `/api/v1/products/search?speed=&technology=` | numeric download-speed filter: `1 Gbps` (exact), `>= 500 Mbps`, `at least 1 Gbps`, `under 500 Mbps`; technology is case-insensitive; 422 on an unparseable speed |
| GET | `/api/v1/categories` | category names |
| POST | `/api/v1/products/compare` | body `{"product_ids": [2..5 ids]}`; 422 outside 2..5; 404 when none exist; `fastest_product_id` computed in Mbps |
| GET | `/api/v1/products/{product_id}/alternatives?criteria=` | `faster`, `similar`, `different_tech`, or omitted (same category); 422 for other values |
| GET | `/api/v1/products/best-value?category=` | highest throughput (Mbps), optionally within a category. There is no budget parameter: pricing is not disclosed by the catalog (offer management handles budget fit) |
| GET | `/api/v1/knowledge/search?q=&top_k=` | `top_k` 1..10 (default 4); `available: false` when the index is not available |

Errors are JSON: `{"error": "not_found" | "invalid_input", "detail": ...}` with HTTP 404 / 422.
OpenAPI docs: `/docs`.

## MCP tools (`/mcp/`)

The names match the legacy in-process tools, so the product agent prompt is unchanged.
Every result is a JSON object (`structuredContent`).

| Tool | Arguments | Result |
|---|---|---|
| `list_available_products` | `category?` | `{products[], count, category}` |
| `get_product_by_id` | `product_id` | product fields + `found: true`, or `{found: false, product_id, message}` |
| `search_products_by_criteria` | `speed?`, `technology?` | `{products[], count, criteria}` |
| `get_product_categories` | none | `{categories[], count}` |
| `compare_products` | `product_ids[]` (2..5) | `{comparison, products_compared, not_found, fastest_product_id, recommendation}` |
| `suggest_alternatives` | `product_id`, `criteria?` | `{base_product, alternatives[], count, criteria}` |
| `get_best_value_product` | `category?` | `{found, recommended, category, reason}` |
| `search_product_knowledge` | `query`, `top_k?` | `{available, query, passages[{text, doc_file, section, product_ids, product_family, distance}], count, message}` |

MCP tools return input errors as data (`success: false, error`) instead of HTTP errors, so the model can recover.

Behaviour changes from the legacy ProductAgent tools:

- Product ids are case-insensitive.
- Speeds are compared numerically in Mbps. The legacy code compared strings, so `"5 Gbps"` beat `"10 Gbps"`.
- `max_price` (search) and `max_budget` (best value) were ignored before and are removed from the tools and the REST API (an unknown query parameter such as `max_budget` is ignored).
- `get_best_value_product` takes an optional `category` instead.
- `suggest_alternatives(criteria="different_tech")` stays within the same product family, e.g. fiber to coax.
- `search_product_knowledge` returns structured passages instead of a preformatted string.

## Environment

| Variable | Required | Default | Notes |
|---|---|---|---|
| `DATABASE_URL` | yes | none | `postgresql://user:pw@host:5432/db` |
| `PORT` | no | `8080` (image) | |
| `CHROMA_PATH` | no | `services/catalog/data/embeddings` (image: `/app/data/embeddings`) | persistent Chroma index |
| `EMBEDDING_MODEL_PATH` | no | none (image: `/app/models/all-MiniLM-L6-v2`) | local sentence-transformers model directory |
| `EMBEDDING_MODEL` | no | `all-MiniLM-L6-v2` | used when `EMBEDDING_MODEL_PATH` is not a directory |
| `RAG_BUILD_ON_START` | no | `true` (image: `false`) | build the index in a background thread when it is empty |
| `DB_POOL_MAX`, `LOG_LEVEL` | no | see `sales_common` | |

## Run locally

```bash
python -m sales_common.migrate --seed                   # from the repo root, with DATABASE_URL set
pip install -e libs/sales_common -e services/catalog
python services/catalog/scripts/ingest_knowledge.py      # optional: build the RAG index
cd services/catalog && uvicorn catalog_service.app:app --port 8101
# agents: CATALOG_MCP_URL=http://localhost:8101/mcp/
```

## Tests

```bash
TEST_DATABASE_URL=postgresql://... pytest services/catalog/tests -q
```

- DB-backed tests are skipped when `TEST_DATABASE_URL` is unset.
- RAG pipeline tests use a deterministic hashing embedder.
- The real embedding-model test runs only when `sentence-transformers` and the model are available.
- The MCP test starts uvicorn on a free port and calls the tools through ADK `McpToolset`.

## Docker

```bash
docker build -f services/catalog/Dockerfile -t catalog-service .
```

The image installs CPU-only PyTorch. At build time it pre-stages the embedding model and builds the Chroma index. At runtime it runs offline (`HF_HUB_OFFLINE=1`).
